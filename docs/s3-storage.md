# S3: Диск и память ИИ

Production использует приватный бакет `vvionspace` на S3-совместимом endpoint. Ключи находятся только в encrypted env Vercel; их значений в репозитории нет. Код Мегадиска, SSH, тарифы, покупки и балансы не менялись.

## Обычный Диск

Новые байты сохраняются в `vvvion/disk/<sha256 owner>/<uuid>`. В прежнем поле `disk_files.data` хранится версионированная ссылка `@vv-s3:1:…` с длиной и SHA-256, старый base64 читается как раньше. Это не публичный URL. Проверка владельца/ссылки общего доступа выполняется до загрузки S3. Проверка SHA-256 не позволяет выдать повреждённый объект за файл.

Обновлены все читатели: скачивание/Range, ZIP, чтение агентом, редактор/предпросмотр проекта и пересылка файла в переписку. Все новые записи на обычный Диск, включая документы и сгенерированные файлы, используют S3. Старые файлы не переносились автоматически. Удаление строки обычного Диска удаляет соответствующий объект; сбой очистки журналируется без содержимого. При сбое между PUT и SQL либо замене могут остаться непривязанные объекты; автоматического удаления по префиксу нет, чтобы не потерять файлы.

## Память ИИ

`VVVION_MEMORY_STORAGE=s3` выбирает S3 вместо SQL-таблиц памяти. Каждому владельцу соответствует один объект `vvvion/memory/<sha256 owner>.json`. Внутри — AES-256-GCM envelope: отдельный случайный IV, тег подлинности и привязка к владельцу через AAD. Ключ шифрования независим от S3 credentials и хранится в encrypted env. Не менять/не удалять его без контролируемого перешифрования существующих объектов.

Факты, согласие, версии, хеши удалённых записей и generation fence коммитятся одним PUT. Провайдер не прошёл проверку условных PUT; поэтому записи сериализованы распределённой транзакционной advisory-блокировкой в существующем Postgres. Самих фактов в Postgres при этом нет. Новые таблицы и миграции для S3-памяти не нужны. Сбой S3 не заменяет память пустой копией; чат продолжает работу без памяти, изменение не подтверждается. Функция доступна вошедшим пользователям, но использование и автоматическое извлечение включаются каждым владельцем отдельно. Автоматика выключена изначально.

120 фактов/аккаунт, 60 изменений/час, 512 хешей удалённых фактов, 256 настроек диалогов. Чистка памяти удаляет факты из текущего объекта и выключает автоизвлечение. Старые сообщения и версии объектов/резервные копии провайдера этим не стираются. Админка не перечисляет объекты аккаунтов и не показывает фиктивные глобальные счётчики.

## Переменные окружения

- `VVVION_S3_ENDPOINT`, `VVVION_S3_REGION`, `VVVION_S3_BUCKET`
- `VVVION_S3_ACCESS_KEY_ID`, `VVVION_S3_SECRET_ACCESS_KEY` — encrypted, server only
- `VVVION_DISK_S3_ENABLED=true`
- `VVVION_MEMORY_STORAGE=s3`
- `VVVION_MEMORY_ENCRYPTION_KEY` — 32 случайных байта в hex, encrypted
- `VVVION_MEMORY_ENABLED=true`, `VVVION_MEMORY_USERS=*` — доступность панели; не согласие пользователя

Выключение `VVVION_DISK_S3_ENABLED` останавливает новые S3-записи, но чтение существующих ссылок продолжает работать. Не удалять S3 credentials и не откатывать приложение на версию ДО поддержки ссылок: та версия не сможет прочитать новые файлы. Для аварийного выключения памяти — `VVVION_MEMORY_ENABLED=false`, не удаляя encrypted объекты и ключ. Смена memory backend на SQL не переносит факты автоматически.

## Проверки

- Реальный бакет: PUT 200, GET 200, точное совпадение байтов; anonymous GET 403; удаление созданного probe 204. Пользовательские объекты не читались и не менялись.
- `scripts/s3-disk.test.mjs`: совместимость base64, отдельные владельцы, приватность, чтение при выключенных новых записях, повреждение.
- `scripts/s3-memory.test.mjs`: шифрование/AAD, подмена, изоляция, параллельные записи под блокировкой, устаревшие версии, согласие, opt-out/delete fence, отсутствие коммита при ошибке.
- `scripts/s3-smoke.mjs`: ручная проверка S3 через stdin без credentials в argv/файлах. Проверка условных PUT намеренно завершается ошибкой на текущем endpoint; runtime от них не зависит.
