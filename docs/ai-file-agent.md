# Файловый агент и резервные провайдеры

Доступ включается пользователем в «Настройки → Мой диск в ИИ-чате» и передаётся
только для его авторизованного запроса. Сервер всегда подставляет владельца из
сессии: клиент и модель не могут выбрать другой user_id.

Инструменты: `my_files`, `my_folders`, `read_my_file`, `create_my_folder`,
`save_my_text`, `write_my_file`. Обычный Диск поддерживает одноуровневые папки;
Мегадиск — вложенные папки и требует действующую подписку. Правка создаёт новую
версию рядом с оригиналом, а не заменяет исходный файл. Для правки нужен `version`
из чтения этого файла в текущем запросе. Частично прочитанный файл изменять нельзя.

Текст читается по 4000 знаков. `next_offset` позволяет дочитать следующую часть,
`max_chars` — выбрать размер до 12000. Старые результаты чтения в истории
сокращаются, сохраняя ID, ссылки и позиции. Файлы больше 256 КБ передаются для
анализа частично, об этом сообщает `unread_bytes`. Бинарные документы не
притворяются прочитанным текстом; у аудио доступны только теги.

Запись файла по умолчанию идёт на Диск и в папку, созданную в этом же запросе, если модель не указала другое. Новые файлы: txt, md, csv, json, py, js, ts, css, html, yaml, yml, xml. Сайт сохраняется по одному файлу за шаг, с полным текстом. На шаге с инструментами у модели есть до 110 секунд и запас токенов на содержимое, чтобы ответ не обрывался после папки. Если запрошены файлы, остановка после одной папки не считается успехом.
Код хранится как текст, не исполняется сервером. JSON проверяется до сохранения.
Лимиты запроса: 12 шагов модели, до 4 инструментов в одном шаге, 8 изменений,
100 КБ на файл, 400 КБ записанного текста. Проверяются квоты и принадлежность
папок. Повтор идентичного успешного вызова возвращает прежний результат.
Запись требует просьбы пользователя в текущем сообщении; инструкции из файлов
не являются разрешением. Сохранённые результаты добавляются в итог со ссылками.

Провайдеры одной модели используются по порядку slot. Каждый новый запрос
начинается с первого. Отказавший провайдер пропускается только до конца текущего
запроса; история инструментов и успешные действия остаются общими. Проверяются
сетевые ошибки, таймаут начала ответа, HTTP-ошибки, ошибки внутри HTTP 200,
пустые ответы и ошибки SSE. При обрыве уже начатого ответа следующий провайдер
получает написанный текст для продолжения без повторного выполнения действий.
Отмена пользователем останавливает переключение. Дневной лимит не списывается
заново для каждой попытки провайдера.

Если провайдер отвергает native tools, тот же провайдер сначала получает простой
JSON-протокол: `{"tool":"имя","arguments":{...}}` либо `{"answer":"текст"}`.
Неверный JSON не исполняется и возвращается модели на исправление. Небольшим
моделям помогают короткие схемы, явные ошибки аргументов, пошаговый системный
промпт и ограниченная история чтений. Способность конкретной модели следовать
протоколу всё равно имеет значение: модель без такой способности не получает
права изображать запись выполненной.

Проверки: `scripts/agent-files.test.mjs` прогоняет JSON-модель через создание
папки, запись, чтение и новую версию с отказом первого провайдера между шагами.
`scripts/provider-router.test.mjs` проверяет порядок, деградацию инструментов,
ошибки 200/SSE, отмену и продолжение потока. `scripts/disk-tools.test.mjs`
проверяет права, аргументы, пределы, чтение и защиту от повторных записей.

Миграция `0051_disk_documents.sql` атомарно расширяет CHECK типа файлов
до image/audio/file. Она не переписывает файлы, пользователей, покупки и баланс.
