# Android 3.0.2 — проверка и передача

Дата: 15 ноября 2026. Ветка: `uiux-polish-3.0.1`. Package: `space.vvvion.app`, versionCode 18, Android 7+ (API 24), target/compile API 36.

## Что изменено

В исходном состоянии ветки Android был представлен инструкцией без собираемого проекта. Восстановлен полноценный проект в `android/`, подключены существующие React UI и серверные функции. Сохранён нативный Java/AndroidX слой: перенос на Capacitor потребовал бы переписывания уже существующих Media3, загрузок, виджетов и разрешений без пользы для общих аккаунтов и данных.

Это онлайн-гибрид: HTML и API приходят с `https://vvvion.space`, статические ресурсы дополнительно упаковываются из текущего checkout и используются только по точному URL. Сборка APK независима от лимита сборок Vercel. Новые серверные функции и интерфейс из ветки появятся после отдельного деплоя сайта. APK не создаёт отдельную базу пользователей, покупок или Вублей.

Исправлены системные отступы Android 16, перекрытие поля ввода навигационной панелью и двойное уменьшение высоты при клавиатуре. Назад обрабатывается через AndroidX. Сохранены native splash/loader, восстановление WebView, экран без сети с повтором, светлая/тёмная тема, поворот, камера/выбор вложений, микрофон, скачивание/открытие, Share, clipboard, haptics, Media3 и уведомления. Наличие модулей не означает прохождение всех сценариев на физическом телефоне.

Усилены мост JS/native (случайная capability для каждого перехода, проверка каждой операции), список доверенных HTTPS URL, обработка редиректов и cookie в медиаплеере, ограничения Base64-скачиваний, очистка частичных файлов и политика кеша. Third-party cookies отключены. Нет отключения SSL-проверки, cleartext или mixed content. Сессия сайта использует приватный WebView cookie store, резервное копирование отключено; нативный слой не сохраняет отдельный bearer token в preferences. В существующем веб-клиенте также есть sessionStorage bearer fallback для preview; полная миграция этой веб-авторизации не выполнялась.

## Что требуется для распространения

1. Прежний keystore и пароли через GitHub Actions Secrets: `VV_KEYSTORE_B64`, `VV_STORE_PASS`, `VV_KEY_ALIAS`, `VV_KEY_PASS`. CI автоматически соберёт подписанные APK/AAB. Новый release-ключ не создавался. Смена сертификата не позволит обновить уже установленное приложение со старой подписью; Debug также не заменяет Release. Не удаляйте приложение с несинхронизированными локальными чатами ради обхода этой ошибки.
2. `VV_FIREBASE_JSON` для CI и действующая серверная FCM-конфигурация. Код FCM включён в передаваемый локальный APK, но доставка реального push не подтверждена.
3. Отпечаток итогового release-сертификата в `/.well-known/assetlinks.json` на сайте для verified App Links. Обычная обработка deep links реализована; верификация домена отдельно не подтверждена.
4. Проверка на физическом устройстве: новый аккаунт/письмо/вход/выход, камера и микрофон с отказом/выдачей разрешения, файловые провайдеры, планшет/landscape IME, уведомления и покупки в разрешённом тестовом окружении. Обещание полного отсутствия багов по результатам smoke-теста было бы неверным.

Все изменения сделаны в рабочей ветке; main не сливался, Production не публиковался, миграции и изменение данных Neon не выполнялись. Текущая отслеживаемая конфигурация не содержит keystore или Firebase JSON; это не замена аудиту всей истории Git.
