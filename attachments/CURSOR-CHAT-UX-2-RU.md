## 2. Сквозной баг P0-0 (все экраны): sheet действий сломан — **сайт**
**Что не так. Измерено.** Тап по пузырю сообщения пользователя («Копировать / Изменить / Удалить») и по «⋯» под ответом ассистента открывает sheet, который **вместо нижней шторки на весь экран рисуется внутри самого сообщения**: на 390 px обёртка `fixed inset-0` имеет размер `[16, 87, 358, 48]` вместо `[0, 0, 390, 844]`, шторка уезжает вверх (`y = -59`), обрезается шапкой и скроллером, затемнения нет. На скриншоте `before-01-m390-sheet-bug-user-bubble.jpg` видна только строка «Удалить». **«Копировать» и «Изменить» недоступны — на телефоне нельзя скопировать и изменить своё сообщение.** На ПК то же (`v2/shots/d1440-32-user-sheet-bug.jpg`).

**Причина (измерено, не догадка).** Строка сообщения имеет `.msg-row{content-visibility:auto; contain-intrinsic-size:auto 320px}` (добавлено ради скорости). `content-visibility:auto` включает `contain: layout paint style`, и такой элемент становится containing block для `position:fixed` потомков и обрезает их. Проверка: `add_style_tag('.msg-row{content-visibility:visible!important}')` → обёртка `[0,0,390,844]`, шторка `[0,650,390,194]` — всё встаёт на место (`v2/before-02-m390-sheet-with-fix-preview.jpg`).

**Как чинить.** Подсказки: `rg -n "rounded-t-3xl border border-line bg-elev" transcript-*.js` (компонент `US`), `rg -n "inset-0 z-\[70\]"`.
1. Главное: рисовать `US` через портал в `document.body` (как уже сделано у шторок в `routes-*.js`, там есть `createPortal`):
```tsx
import { createPortal } from 'react-dom';

export function BottomSheet({ title, onClose, children }: { title: string; onClose(): void; children: React.ReactNode }) {
  useEffect(() => {
    const onKey = (e: KeyboardEvent) => e.key === 'Escape' && onClose();
    window.addEventListener('keydown', onKey);
    return () => window.removeEventListener('keydown', onKey);
  }, [onClose]);
  return createPortal(
    <div className="fixed inset-0 z-[70] flex items-end justify-center bg-black/45 md:items-center" onClick={onClose}>
      <div role="dialog" aria-modal="true" aria-label={title}
           className="w-full max-w-lg rounded-t-3xl border border-line bg-elev px-3 pt-2 pb-[max(0.75rem,env(safe-area-inset-bottom))] md:rounded-3xl"
           onClick={(e) => e.stopPropagation()}>
        {/* ручка + перетаскивание вниз — см. раздел 5, хук useSheetDrag */}
        <div className="mx-auto mb-1 h-1.5 w-10 rounded-full bg-line-strong md:hidden" aria-hidden />
        <p className="px-2 py-2 text-center text-xs text-faint">{title}</p>
        <div className="flex flex-col gap-1">{children}</div>
      </div>
    </div>,
    document.body,
  );

```
2. Страховка: у последних 3 строк списка (и у любой строки со стримом) `content-visibility` отключить: `.msg-row:nth-last-child(-n+3){content-visibility:visible}`.
3. Пересмотреть остальные `fixed`-потомки внутри `.msg-row` (лайтбокс картинки `BS`, предпросмотр HTML «На весь экран» в `Sk`) — они сломаны по той же причине. **[проверить]** и перенести в портал.
**Приёмка.** На 390×844 тап по пузырю → шторка прижата к низу, фон затемнён на весь экран, три строки по 44–48 px видны и нажимаются; Esc и тап по фону закрывают; лайтбокс картинки и HTML-предпросмотр открываются на весь экран.

## 3. ПК — что улучшить

### P0-1. Горячие клавиши — их нет совсем — **сайт**
**Что не так. Измерено.** `Esc` во время стрима **не останавливает** ответ (текст рос 896 → 1511 → 2114 знаков после нажатия). `Ctrl/⌘+K`, `/`, `Ctrl+Shift+O`, `Ctrl+B`, `↑` в пустом поле — ничего не делают. После загрузки страницы фокус на `BODY` (поле не в фокусе), набор текста «вслепую» уходит в никуда. Enter / Shift+Enter в поле работают правильно (Shift+Enter → новая строка, поле растёт 44 → 92 → максимум 200 px).

**Набор (как у ChatGPT/Claude на ПК):**
| Клавиши | Действие |
|---|---|
| `Enter` / `Shift+Enter` | отправить / новая строка (**уже есть**, не трогать; но не отправлять при `e.isComposing` / `keyCode===229` — ввод через IME) |
| `Esc` | если идёт ответ — остановить (та же функция, что кнопка «Стоп»; в коде ищи `mode:"stop"`); иначе закрыть sheet/popover/сайдбар-оверлей; иначе снять фокус с поля |
| `Ctrl/⌘+K` | фокус в «Поиск по истории» (если сайдбар скрыт — открыть) |
| `Ctrl/⌘+Shift+O` | новый чат |
| `Ctrl/⌘+B` | показать/скрыть сайдбар |
| `/` | фокус в поле ввода, когда фокус не в поле |
| `↑` в **пустом** поле | править последнее своё сообщение (тот же `onEdit`, что у пункта «Изменить») |
| `Ctrl/⌘+Shift+C` | скопировать последний ответ |
| `Ctrl/⌘+/` | окно «Горячие клавиши» |
| набор букв без фокуса | печатный символ при фокусе на `BODY` → фокус в поле, символ остаётся |

```tsx
// src/features/chat/useChatShortcuts.ts
type Api = { stop(): void; isStreaming(): boolean; newChat(): void; toggleSidebar(): void;
             focusSearch(): void; editLast(): void; copyLast(): void; closeTopLayer(): boolean };

export function useChatShortcuts(api: Api) {
  useEffect(() => {
    const onKey = (e: KeyboardEvent) => {
      if (e.isComposing || e.keyCode === 229) return;
      const mod = e.ctrlKey || e.metaKey;
      const t = e.target as HTMLElement | null;
      const typing = !!t && (t.tagName === 'INPUT' || t.tagName === 'TEXTAREA' || t.isContentEditable);
      const composer = t?.id === 'composer';

      if (e.key === 'Escape') {
        if (api.closeTopLayer()) { e.preventDefault(); return; }
        if (api.isStreaming()) { e.preventDefault(); api.stop(); return; }
        if (composer) (t as HTMLElement).blur();
        return;
      }
      if (mod && e.key.toLowerCase() === 'k') { e.preventDefault(); api.focusSearch(); return; }
      if (mod && e.shiftKey && e.key.toLowerCase() === 'o') { e.preventDefault(); api.newChat(); return; }
      if (mod && e.key.toLowerCase() === 'b') { e.preventDefault(); api.toggleSidebar(); return; }
      if (mod && e.shiftKey && e.key.toLowerCase() === 'c') { e.preventDefault(); api.copyLast(); return; }
      if (e.key === 'ArrowUp' && composer && !(t as HTMLTextAreaElement).value && !e.shiftKey) { e.preventDefault(); api.editLast(); return; }
      if (!typing && !mod && !e.altKey) {
        if (e.key === '/') { e.preventDefault(); document.getElementById('composer')?.focus(); return; }
        if (e.key.length === 1) document.getElementById('composer')?.focus(); // символ допечатается в поле
      }
    };
    window.addEventListener('keydown', onKey);
    return () => window.removeEventListener('keydown', onKey);
  }, [api]);
}
```
- Подсказки: `title="Новый чат (Ctrl+Shift+O)"` у кнопок, «Стоп» → `Стоп · Esc`; в окне `Ctrl+/` — таблица выше. Для macOS показывать ⌘ вместо Ctrl.
- На ПК после загрузки и после «Новый чат» — `autoFocus` в поле (на сенсорных **не** фокусировать: откроется клавиатура).
**Приёмка.** Автотест Playwright (мок SSE): Esc останавливает стрим за ≤ 300 мс, «Остановлено» виден; `Ctrl+K` ставит фокус в поиск; `↑` в пустом поле открывает редактирование последнего сообщения; `/` и набор буквы возвращают фокус в поле; при открытой шторке первый Esc закрывает шторку, а не стрим.

### P0-2. Планшет и узкое окно: сайдбар съедает 39% — **сайт**
**Что не так. Измерено.** При 768 px (и в окне браузера 800–1000 px) сайдбар `296 px` остаётся постоянным: на чат — 472 px, колонка текста 388 px, 46 знаков, заголовок чата в шапке пропадает, композер со вторым рядом кнопок «Картинка», «Сеть», «Отправить» сжат (`before-03-t768-sidebar-cramped.jpg`). Брейкпоинт, при котором появляется постоянный сайдбар, — `md` (768 px), хотя на 768–1023 нужна «мобильная» схема с выдвижной шторкой.
**Как чинить.** Постоянный сайдбар — с `lg` (≥1024), ниже — шторка (как сейчас на `<768`); на 1024–1279 ширина `18rem`, дальше `18.5rem`. Состояние «скрыто/показано» на ПК запоминать в `localStorage` (`vv.sidebar`), по умолчанию: ≥1280 показан, 1024–1279 показан, <1024 скрыт. Подсказка: `rg -n "w-\[min\(100%,18.5rem\)\]" routes-*.js` (это `aside`), условие `matchMedia('(max-width: 767px)')` (два места в `routes-*.js`) заменить на `(max-width: 1023px)`.
```ts
export function useSidebarMode() {
  const lg = useMediaQuery('(min-width: 1024px)');
  const [open, setOpen] = useState(() => localStorage.getItem('vv.sidebar') !== '0');
  const toggle = () => setOpen(v => { localStorage.setItem('vv.sidebar', v ? '0' : '1'); return !v; });
  return { overlay: !lg, visible: lg ? open : false, open, toggle }; // на overlay-режиме состояние хранится отдельно в useState
}
```
**Приёмка.** 768×1024: сайдбар скрыт, чат занимает 768 px, колонка текста ≥ 700 px; кнопка ☰ открывает шторку; 1024×768 и выше: сайдбар показан, состояние переживает перезагрузку.

### P0-3. Сообщение пользователя на ПК: нет действий и доступа с клавиатуры — **сайт**
**Что не так. Измерено + по коду.** Пузырь пользователя — `div` с `onClick` (`RS` в `transcript-*.js`, подсказка: `window.getSelection()?.toString()||d(!0)`), без `role`, `tabindex`, `cursor`. Клавиатурой до «Копировать / Изменить / Удалить» не добраться, на hover ничего не появляется (кнопок внутри сообщения 0). У старых ответов ассистента единственная кнопка — «⋯» отдельной строкой (44 px высоты + 8 px отступ на каждый ответ), у последнего — полный ряд (копировать, заново, удалить 40×40).
**Как чинить (ПК, `@media (hover:hover) and (pointer:fine)`):**
- Под пузырём пользователя и под каждым ответом — панель действий, видимая при `:hover` и `:focus-within` (opacity 0 → 1, 120 мс), у **последнего** ответа — всегда. Кнопки 32×32 (визуально), зона нажатия 36×36, `aria-label`, `title`.
- Пузырь: `role="button" tabIndex={0}`, `Enter/Space` открывают то же меню на мобильных; на ПК тап по пузырю **ничего не открывает** (убрать sheet на `md+`), чтобы не мешать выделению текста.
- «⋯» на ПК — popover вместо sheet (позиционирование от кнопки), на мобильных остаётся sheet.
**Приёмка.** Tab доходит до панели действий каждого сообщения, ← → переключают кнопки, Enter срабатывает; на hover панель появляется без сдвига вёрстки (`min-height` резервируется); у старых ответов нет отдельной строки «⋯».

### P1-1. Сайдбар: действия съедают заголовок, «Удалить все» слишком заметно — **сайт**

В списке постоянно висит красная кнопка «Удалить все» 279×40 прямо под поиском — случайное нажатие стирает всю историю.
**Как чинить.**
- Оставить при hover/focus-within **одну** кнопку «⋯» (32×32) → popover «Переименовать / Скачать .md / Скачать .json / Удалить»; заголовок получает всю ширину и `mask-image: linear-gradient(90deg,#000 85%,transparent)` вместо многоточия.
- «Удалить все» — в меню «⋯» рядом с «Новый чат» или в Настройки → Данные; подтверждение шторкой/диалогом на сайте (не `window.confirm`), а удалённый одиночный чат — snackbar «Удалено · Отменить» (5 с).

## 5. Приложение (WebView): что делает APK, что сайт

Каждый пункт — отдельная задача. «Сайт» — Cursor; «APK (сделает Гик)» — код приложения.

### A-1. Нативная «Назад»: закрыть слой, а не страницу — **APK (сделает Гик)** + **сайт**
**Проблема.** Сейчас системная «Назад» в приложении ходит по истории WebView или сворачивает приложение (в мосте: на главной при музыке сворачивает). Открытые sheet / сайдбар-шторка / popover модели при этом не закрываются — человек теряет место в чате.
**Протокол.**
- APK: `OnBackPressedCallback` (API 33+: `onBackInvokedDispatcher`) → `webView.evaluateJavascript("(window.__vvvionHandleBack&&window.__vvvionHandleBack())===true", cb)`. Если вернулось `true` — событие поглощено; иначе — прежнее поведение (история / свернуть).
- Сайт:
```ts
// src/lib/app-back.ts
const layers: Array<() => void> = [];          // стек закрывалок: sheet, popover, сайдбар-шторка, лайтбокс
export const pushBackLayer = (close: () => void) => { layers.push(close); return () => { const i = layers.lastIndexOf(close); if (i >= 0) layers.splice(i, 1); }; };
(window as any).__vvvionHandleBack = () => { const c = layers.pop(); if (!c) return false; c(); return true; };
```
`BottomSheet`, шторка сайдбара, popover модели, лайтбокс при монтировании вызывают `pushBackLayer(onClose)` (в `useEffect` с возвратом очистки). То же самое используется для `Esc` на ПК (`closeTopLayer = () => __vvvionHandleBack()`).
**Приёмка.** Открыть шторку → «Назад» закрывает её, остаёмся в чате; второе «Назад» → поведение как раньше.

### A-2. Цвет статус-бара и навигации следует теме сайта — **APK (сделает Гик)**; сайт уже готов
**Измерено / по коду.** Мост 2.8.0 зашивает бары, окно и пластину в `#0c0c0e`, `windowLightStatusBar=false`. Тема сайта переключается (тёмная `#0c0c0e`, светлая `#f4f2ee`), и сайт при переключении сам меняет `<meta name="theme-color">` (функция `po()` в `routes-*.js`: `content` = `#f4f2ee` / `#0c0c0e`) и класс `html.light`. На светлой теме верхняя пластина остаётся чёрной — «чёрная дыра» над светлым чатом.
**Что сделать в APK.** В инжектируемом скрипте — `MutationObserver` на `meta[name=theme-color]` (атрибут `content`) и на `class` у `<html>`; по изменению вызывать `Android.onTheme('#f4f2ee', true)`; нативная сторона: `statusBarColor/navigationBarColor`, цвет `topScrim`, цвет окна и `DecorView`, `WindowInsetsControllerCompat.isAppearanceLightStatusBars = isLight`, `isAppearanceLightNavigationBars = isLight`. Стартовое значение — из `localStorage('yaronetic.theme')`, чтобы не мигало на холодном старте (тот же ключ читает ранний скрипт сайта).
**Сайт:** ничего, кроме гарантии, что `meta[name=theme-color]` всегда обновляется при смене темы (в т. ч. при «системной»).
**Приёмка.** Переключить тему на светлую → статус-бар и нижняя навигация светлые, иконки тёмные; клавиатура → полосы не появляются; холодный запуск в светлой теме без чёрной вспышки.

### A-3. Высота клавиатуры и «жив ли ввод» — **APK (сделает Гик)** + **сайт**
**Зачем.** `adjustResize` сжимает окно, а сайт на `100dvh` подстраивается, но не знает, что клавиатура открыта (нечем скрывать гостевую полоску, ограничивать поле, держать прилипание).
**APK:** по `WindowInsetsCompat.Type.ime()` отдавать `window.dispatchEvent(new CustomEvent('vvvion-app-keyboard',{detail:{open:true,height:<css px>}}))` и выставлять `document.documentElement.style.setProperty('--kb', '<px>')` и класс `vv-kb-open` (без циклов, идемпотентно, как `applyBarColors()`).
**Сайт:** `html.vv-kb-open .guest-strip{display:none}`, `#composer{max-height:min(200px,30dvh)}`, при открытии клавиатуры — `scrollIntoView` поля и сохранение «прилипания» к низу; без приложения то же даёт `visualViewport` (fallback).
**Приёмка.** Открыл клавиатуру → гостевая полоска скрыта, последнее сообщение видно целиком, при закрытии нет прыжков.

### A-4. Нативное «Поделиться» и буфер — **APK (сделает Гик)** + **сайт**
`VvvionApp.share({ text, title?, url? })` → `Intent.ACTION_SEND` (`text/plain`) + `Intent.createChooser`. Сайт вызывает его в «Поделиться» у ответа/чата, если `isApp()`; иначе `navigator.share`/копирование. Копирование (`navigator.clipboard`) в WebView работает через запасной `execCommand` (в коде есть); при желании `VvvionApp.copy(text)` → `ClipboardManager` и системный тост Android 13+.
**Приёмка.** «Поделиться» в приложении открывает системный список, текст ответа в виде простого текста.

### A-5. Вибрация: точки в чате — **сайт** (API уже в приложении, типы — в мосте 2.8.0)
Использовать `haptic()` из `src/lib/haptic.ts` (мост, раздел «вибрация»). В чате:
| Момент | Тип |
|---|---|
| Отправка | `medium` |
| Открытие sheet / шторки сайдбара | `light` |
| Выбор модели, переключатели в «+» | `selection` |
| Пересечение порога жеста (свайп-ответ, свайп по чату) | `selection` |
| Срабатывание жеста (цитата вставлена, чат удалён) | `light` / `heavy` (удаление) |
| Долгое нажатие на сообщении (после 450 мс) | `heavy` |
| Ответ закончился при активной вкладке | `success` (не чаще раза в 3 с) |
| Ошибка / 429 | `error` |
Не вызывать в цикле, на прокрутке и во время стрима по токенам. При `html.vv-reduce-motion`/`prefers-reduced-motion` — оставлять только `success/error`.

### A-6. Жесты в приложении: что НЕ делать нативно — **APK (сделает Гик)**
- **Не** перехватывать касания нативно (в 2.8.0 `onTouch` нет — оставить так), **не** включать нативный PTR (`VvvionApp.pullToRefresh(false)` по умолчанию) — сайтовый PTR из моста остаётся единственным.
- **Не** использовать `setSystemGestureExclusionRects` для левого края: системная «Назад» важнее; зона старта нашего жеста сдвинута (раздел 5.0).
- Отключить системное меню «выделить» на пузырях сообщений на время долгого нажатия делает сайт (`user-select:none` + `-webkit-touch-callout:none` на `.bubble` пока идёт таймер), нативно ничего не нужно.
- Прочее (уведомления, push, плеер) — как в мосте 2.8.0.

## 6. Свайпы и жесты

### 6.0. Правила (общие)
| Правило | Значение |
|---|---|
| Где включать горизонтальные жесты | только `html.vv-app` **или** `display-mode: standalone` (там нет браузерного «назад»). В обычной вкладке Chrome/Safari горизонтальный свайп отдан браузеру; все действия остаются на кнопках |
| Старт жеста | смещение ≥ **12 px**; горизонтальный, если `|dx| > 1.5·|dy|`; вертикальный — отдаём скроллу, жест отменяем |
| Зона начала для «открыть сайдбар» | `x ≥ 24 px` от края (системная «Назад» Android занимает ~0–24 dp; не пытаться отобрать её) и только на не-прокручиваемом по X элементе |
| Фиксация | после захвата горизонтали — `setPointerCapture`, элемент следует за пальцем 1:1 (с резинкой за порогом), `will-change: transform` только на время жеста |
| Фиксирование действия | сдвиг ≥ **35–40%** ширины/высоты цели **или** скорость ≥ **0.5 px/мс** в сторону действия |
| Отмена | `pointercancel`, вертикальный сдвиг > 24 px до фиксации, второй палец, смена `visibilitychange` |
| Конфликт с горизонтальным скроллом | жест игнорируется, если касание началось внутри `.scroll-x`, `pre`, `.code-frame`, `.katex-display`, `input`, `textarea`, `[data-no-swipe]` |
| Конфликт с выделением текста | долгое нажатие на **ассистенте** не перехватываем (оставляем нативное выделение); на пузыре **пользователя** — перехватываем (текст копируется через sheet) |
| Конфликт с PTR | вертикаль сверху — только сайтовый PTR (мост, «P0 — касания»); наши жесты вертикаль не трогают, кроме перетаскивания sheet за ручку |
| `touch-action` | у жестовых контейнеров `touch-action: pan-y` (вертикаль нативно, горизонталь — наша). Нестед-скроллеры (`.scroll-x`) имеют свой `pan-x pan-y` — **[проверить на устройстве]**, что пересечение `touch-action` по цепочке не блокирует их горизонтальный скролл |
| Reduced motion | `prefers-reduced-motion` или `html.vv-reduce-motion`: без пружин и смещений, действие по порогу срабатывает мгновенно; кнопки остаются |
| Haptics | см. A-5, `haptic('selection')` при пересечении порога, `haptic('light'|'heavy')` при действии |

### 6.2. Реализация (под реальную структуру)
**Хук свайпа (pointer events, пассивный).** Подключать к строке сообщения (`<Td.article className="msg-row …">` в списке `Bk`) и к строке чата в `aside` (`routes-*.js`).
```ts
// src/lib/gestures/useSwipe.ts
import { useRef } from 'react';

type Opts = {
  axis: 'x';
  startPx?: number;               // 12
  commit?: (dx: number, v: number) => boolean;   // true → зафиксировать
  onMove?: (dx: number) => void;  // тянем элемент
  onCommit?: (dir: 1 | -1) => void;
  onCancel?: () => void;
  enabled: boolean;               // isApp() || standalone, !reducedMotion → без анимаций, но с коммитом
  ignore?: string;                // селектор исключений
};

export function useSwipe(o: Opts) {
  const s = useRef({ x: 0, y: 0, t: 0, id: -1, locked: false, dead: false });
  const IGN = o.ignore ?? '.scroll-x,pre,.code-frame,.katex-display,input,textarea,[data-no-swipe]';
  const start = o.startPx ?? 12;

  return {
    style: { touchAction: 'pan-y' } as const,
    onPointerDown(e: React.PointerEvent) {
      if (!o.enabled || e.pointerType === 'mouse' || !e.isPrimary) return;
      if ((e.target as Element).closest(IGN)) { s.current.dead = true; return; }
      Object.assign(s.current, { x: e.clientX, y: e.clientY, t: performance.now(), id: e.pointerId, locked: false, dead: false });
    },
    onPointerMove(e: React.PointerEvent) {
      const c = s.current; if (c.dead || e.pointerId !== c.id) return;
      const dx = e.clientX - c.x, dy = e.clientY - c.y;
      if (!c.locked) {
        if (Math.abs(dy) > 24 && Math.abs(dy) > Math.abs(dx)) { c.dead = true; return; }        // вертикаль — скроллу
        if (Math.abs(dx) < start || Math.abs(dx) < 1.5 * Math.abs(dy)) return;
        c.locked = true;
        (e.currentTarget as HTMLElement).setPointerCapture(e.pointerId);
      }
      o.onMove?.(dx);
    },
    onPointerUp(e: React.PointerEvent) {
      const c = s.current; if (!c.locked || c.dead) { c.dead = false; return; }
      const dx = e.clientX - c.x, v = dx / Math.max(1, performance.now() - c.t);
      c.locked = false;
      const ok = o.commit ? o.commit(dx, v) : false;
      if (ok) o.onCommit?.(dx > 0 ? 1 : -1); else o.onCancel?.();
    },
    onPointerCancel() { const c = s.current; if (c.locked) o.onCancel?.(); c.locked = false; c.dead = false; },
  };
}
```
**Свайп-ответ на сообщении (G3).**
```tsx
function SwipeToQuote({ children, onQuote }: { children: React.ReactNode; onQuote(): void }) {
  const ref = useRef<HTMLDivElement>(null);
  const crossed = useRef(false);
  const app = useIsAppOrStandalone();

    axis: 'x', enabled: app,
```

```ts
useEffect(() => {
  if (!enabled) return;
  let x0 = 0, y0 = 0, t0 = 0, active = false, locked = false;
  const IGN = '.scroll-x,pre,.code-frame,.katex-display,input,textarea,[data-no-swipe]';
  const down = (e: PointerEvent) => { if (e.pointerType === 'mouse' || e.clientX < 24 || (e.target as Element).closest(IGN)) return; x0 = e.clientX; y0 = e.clientY; t0 = performance.now(); active = true; locked = false; };
  const move = (e: PointerEvent) => { if (!active) return; const dx = e.clientX - x0, dy = e.clientY - y0; if (!locked && Math.abs(dy) > 24 && Math.abs(dy) > Math.abs(dx)) active = false; else if (Math.abs(dx) > 12 && Math.abs(dx) > 1.5 * Math.abs(dy)) locked = true; };
  const up = (e: PointerEvent) => { if (!active || !locked) { active = false; return; } active = false; const dx = e.clientX - x0, v = dx / Math.max(1, performance.now() - t0); if (dx > 120 || v > 0.5) { haptic('light'); openSidebar(); } };
  addEventListener('pointerdown', down, { passive: true }); addEventListener('pointermove', move, { passive: true });
  addEventListener('pointerup', up, { passive: true }); addEventListener('pointercancel', () => { active = false; }, { passive: true });
  return () => { removeEventListener('pointerdown', down); removeEventListener('pointermove', move); removeEventListener('pointerup', up); };
}, [enabled]);
```

Для шторки (G2) тот же `useSwipe` с отрицательным `dx` на `aside` и на затемнении; прогресс — `translateX(min(0, dx))`, затемнение `opacity = 1 - |dx|/width`.
**Долгое нажатие (G4).**
```ts
export function useLongPress(cb: () => void, ms = 450) {
  const t = useRef(0), x = useRef(0), y = useRef(0), fired = useRef(false);
  return {
    onPointerDown(e: React.PointerEvent) { if (e.pointerType === 'mouse') return; fired.current = false; x.current = e.clientX; y.current = e.clientY;
      t.current = window.setTimeout(() => { fired.current = true; haptic('heavy'); cb(); }, ms); },
    onPointerMove(e: React.PointerEvent) { if (Math.hypot(e.clientX - x.current, e.clientY - y.current) > 10) window.clearTimeout(t.current); },   // скролл ≠ долгое нажатие
    onPointerUp() { window.clearTimeout(t.current); },
    onPointerCancel() { window.clearTimeout(t.current); },
    onContextMenu(e: React.MouseEvent) { if (fired.current) e.preventDefault(); },   // не показывать нативное меню, если наше уже открылось
    className: 'select-none [-webkit-touch-callout:none]',   // только для пузыря пользователя
  };

```
Одиночный тап по пузырю больше не открывает sheet (сейчас `onClick` с проверкой `getSelection()`): тап = ничего, длинное нажатие = sheet, на ПК — hover-панель (P0-3).
**Свайп строки чата (G5).** `useSwipe` на строке `aside`: `translateX(clamp(dx,-144,0))`, под строкой — две кнопки по 72 px (`Закрепить`, `Удалить`); полный свайп → `onDelete` со snackbar. Подсказка: цикл `T.map(([group, items]) => …)` в компоненте списка `aside` (`routes-*.js`, строка с `e&&t?…fixed inset-0 z-30 bg-black/45`).
**Перетаскивание sheet (G6).** Использовать пороги из моста (96 px и 0.4 px/мс), `touch-action:none` — **только** на ручке; тело шторки скроллится (`overscroll-behavior:contain`). Измерено: `+`-sheet закрывается свайпом вниз на 250 px и по телу шторки; `US` (sheet действий) закрывается только Esc/фоном — перевести на общий `BottomSheet` из P0-0 вместе с перетаскиванием.
**Приёмка (жесты).** Синтетические проверки Playwright/CDP + проверка пальцем: (1) G1 открывает шторку только в `vv-app`; в обычной вкладке не срабатывает и браузерный «назад» не нарушен; (2) вертикальный скролл ленты не вызывает смещения сообщений; (3) свайп по таблице скроллит таблицу, а не цитирует сообщение; (4) G3 при `prefers-reduced-motion` вставляет цитату без анимации; (5) долгое нажатие 450 мс на пузыре — sheet + вибрация, лёгкий скролл пальцем — нет; (6) на Android с жестовой навигацией свайп от самого края — системная «Назад», наш G1 — от 24 px.
