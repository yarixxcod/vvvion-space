Разработка Yaronetic AI — премиального одностраничного AI-чата

Создай полноценное, готовое к запуску веб-приложение — универсальный AI Chat Playground с премиальным дизайном. Это должен быть работающий продукт, а не статичный макет.

1. Технологии

- React + TypeScript + Vite.
- Tailwind CSS для стилизации.
- Framer Motion (Motion) для анимаций.
- Lucide React для иконок.
- Поддержка Markdown, таблиц, списков и подсветки кода.
- Используй актуальные стабильные версии библиотек.
- Архитектура должна быть понятной, модульной и расширяемой.

2. Дизайн

Создай современный интерфейс в эстетике премиальных AI-продуктов.

- Основная тема: глубокий графитовый/почти чёрный фон.
- Акценты: мягкий фиолетовый, лавандовый и немного холодного синего.
- Полупрозрачные поверхности, тонкие границы, деликатное свечение, аккуратные тени.
- Большие скругления, свободное пространство, качественная типографика.
- Никакого визуального мусора, чрезмерных градиентов и перегруженных карточек.
- Предусмотри полноценную светлую тему.
- Полная адаптация для смартфонов, планшетов и десктопов.

Название приложения: Nexus AI. Сделай его настраиваемым.

3. Основной экран

Создай SPA с двумя состояниями: приветственный экран и активный чат.

Приветственный экран:

- Логотип и название.
- Красивый анимированный AI-объект.
- Заголовок «Что создадим сегодня?».
- Краткое описание.
- Несколько карточек-примеров запросов.
- Большое поле ввода с кнопкой отправки.
- Выбор активного провайдера и модели.

После первого сообщения приветственный экран плавно превращается в полноценный чат без перезагрузки страницы.

4. Чат

Реализуй:

- Настоящие запросы к API, а не имитацию ответов.
- Streaming через fetch и чтение ReadableStream, если провайдер поддерживает SSE.
- Поддержку OpenAI-compatible Chat Completions API.
- Сохранение истории сообщений в контексте диалога.
- Markdown, таблицы, списки, цитаты и блоки кода.
- Кнопки копирования текста и кода.
- Повторную генерацию ответа.
- Редактирование и повторную отправку пользовательского сообщения.
- Остановку генерации через AbortController.
- Индикатор набора ответа.
- Отображение ошибок API в понятном виде.
- Автоматическую прокрутку с учётом ручной прокрутки пользователя.
- Отображение времени ответа и доступных данных об использовании токенов.
- Удобный многострочный композер с автоувеличением высоты.
- Отправку через Enter и новую строку через Shift+Enter.

Не показывай выдуманные токены, скорость или время генерации. Отображай только фактические данные, полученные от API.

5. Настройки API

Создай красивую модальную панель настроек со следующими полями:

- Название подключения.
- Base URL.
- API Key.
- Дополнительные HTTP-заголовки.
- Endpoint для Chat Completions.
- Список моделей с возможностью ручного добавления.
- Кнопка загрузки моделей через GET /v1/models.
- Проверка подключения.
- Выбор активной модели.
- Системный промпт.
- Temperature и max_tokens.
- Возможность иметь несколько независимых конфигураций провайдеров.

Обеспечь совместимость с API, использующими формат OpenAI Chat Completions. Не предполагай, что абсолютно все сторонние провайдеры поддерживают одинаковые параметры и формат SSE. Нормализуй ответы и корректно обрабатывай несовместимости.

Не добавляй жёсткую привязку к OpenAI: пользователь должен иметь возможность указать любой совместимый сервер.

6. История

Сделай боковую панель:

- Новый чат.
- Список предыдущих диалогов.
- Поиск по истории.
- Переименование.
- Удаление с подтверждением.
- Группировка по датам.
- Экспорт диалога в Markdown или JSON.

Используй IndexedDB для истории и localStorage только для небольших пользовательских настроек. Предусмотри очистку всех локальных данных.

7. Анимации

Продумай анимации всей системы.

Фон:

- Несколько медленно движущихся размытых градиентных пятен.
- Лёгкое зерно.
- Ненавязчивые частицы вокруг AI-объекта.
- Никаких тяжёлых бесконечных эффектов, снижающих производительность.

Интерфейс:

- Плавное появление боковой панели.
- Переход приветственного экрана в чат.
- Появление сообщений с лёгким fade + translate.
- Пульсация трёх точек при ожидании ответа.
- Эффект появления токенов во время потоковой генерации.
- Мягкая подсветка кнопок при наведении.
- Плавное раскрытие меню и настроек.
- Микроанимации переключения моделей и тем.
- Toast-уведомления при копировании и сохранении.

Используй transform и opacity там, где это возможно. Учитывай prefers-reduced-motion. Не запускай тяжёлые анимации для каждого отдельного токена.

8. Безопасность

Ключи нельзя передавать в сторонние аналитические системы или выводить в логи. Скрывай ключ в интерфейсе и предоставь возможность удалить его.

Для статической локальной версии предупреди пользователя, что запросы идут непосредственно к провайдеру и ключ хранится в браузере. Не утверждай, что браузерное хранение обеспечивает абсолютную защиту.

Если приложение размещается публично, предусмотрите серверный прокси с хранением ключей на сервере, ограничением запросов, валидацией входных данных и защитой от злоупотреблений. Не помещай секретные ключи в исходники, Vite-переменные VITE_* или публичный репозиторий.

Не отключай проверку TLS. Не используй eval. Корректно обрабатывай CORS, сетевые ошибки, таймауты и отмену запросов.

9. Качество

- Никаких фиктивных кнопок.
- Никаких случайных демонстрационных ответов вместо API.
- Никаких пустых обработчиков.
- Не оставляй TODO вместо основной функциональности.
- Все состояния загрузки, ошибки и пустые состояния должны быть оформлены.
- Добавь README с командами установки и запуска.
- Добавь пример конфигурации без настоящих ключей.
- Проверь TypeScript, сборку и основные пользовательские сценарии.

Сначала продумай структуру проекта, затем реализуй все основные компоненты, подключение API, хранение данных и анимации. В результате предоставь полный проект, который можно установить и запустить локально.
